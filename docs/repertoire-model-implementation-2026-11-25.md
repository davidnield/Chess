## Implemented

1. **Explicit evaluation bindings.** `eval_binding.py` and `build_budget_books.py --eval-binding` select an immutable 128-bit lookup without rewriting historical count files. The binding checks the manifest hash; explicitly bound lookups check each array when first opened. Book metadata records the binding and its hash. Sweep commands and the coordinator validate consumption. The two real generation bindings are under `evidence/repertoire-model-implementation-20261125/`; they identify generations, not production acceptance.
2. **Paired source scenarios.** `sweep.scenarios.source_arm` derives distinct IDs from the approved Black pilot and each binding. Coordinator schema 2 permits exactly these two versions, requires otherwise identical inputs and a common referee binding, and preserves normal manifest restrictions for other runs. Joint verification permits different stored CP for shared legal move/count evidence and closes comparisons against every arm's own score vector. Counts and child identities must still agree. Common-overlay, monotone-quality and transposition safeguards remain.
3. **Shared native policy arithmetic.** `human_policy.rs` implements the existing OTB ensemble and the new weak-count-plus-Maia policy. Opponent parameters are unchanged. Own observations remain at support 0/1/19/20/21; the new path never substitutes adult counts. The independent Python opponent formula remains a test oracle. Complete legal vectors are validated. Own strengths/ratings/temperatures are explicit engineering choices from the 36-cell grid, not selected production settings.
4. **Batched providers and caches.** `human_providers.py` supplies the own policy; `FrontierOverlay.conditional` supplies the opponent policy. The same adapters feed native W/R and native rollouts. Model, runtime, input, native-code and recipe identities enter the derived-policy caches. Writes commit per batch, with immutable first-writer results. The later [raw-prediction cache and partitioned input milestone](pool-publication-and-prediction-cache-2026-11-25.md) adds persistent pre-temperature vectors shared across downstream recipes. Complete exported count pools supersede selective explorer materialization; a separate persistent query-result cache has not been added.
5. **Native bounded W/R.** `RsContinuation` owns legal replay, full-key interning, transpositions by `(position, remaining depth)`, exact board terminals and backwards induction. W uses two plies; R uses three. Python supplies batched count/model/lookup I/O. Small probabilities are preserved. Missing evaluations and unexpanded branches retain `[0,1]` intervals propagated through the complete probability vector. Root bounds are written to `<prefix>.continuation.json` with full external keys.
6. **Builder integration.** `--continuation-config` keeps the selective provider alive after graph collection, queries off-graph boards, and freezes the union of opponent records used by collection and W/R. Independent local CP overrides the bound lookup. Scalar optimization is refused if any requested root has unresolved width above numerical roundoff. No ancestor value or neutral 0.5 is presented as an evaluated continuation. Legacy sampled-stop/other and dump paths are refused under this contract.
7. **Separated evidence depth and construction counts.** The contract distinguishes candidate, count, upstream-source and evaluation caps. Count metadata must match the evidence cap; OTB must use the matching training-role export. Deeper policy counts can differ from candidate/outcome counts: probabilities use the former, historical outcomes and move mass use the latter. Sweep binding checks permit this distinction. Broader real input access is not yet published.
8. **Ending and utility semantics.** The opt-in `conditional-board-v1` path conditions play on a live board. Source truncation is not an opponent action. Historical endings/censoring remain in raw data and separate policy diagnostics; they do not become board transitions in this diagnostic model. Exact board terminals are native. The new utility consistently uses the source-normalized ±2,000 CP domain and Lichess curve, without a hidden ±1,000 boundary clip. Historical ending treatment and the old utility remain controls pending the empirical/ranking audit.
9. **Native referee precision and continuity.** Rollout CP fields now use float64 through starts, lookup updates, ancestor diagnostics and returned leaves; integer callers remain accepted. `convertibility_eval.rollouts(..., policies=...)` uses shared providers. `sweep.referee.play` returns bounds/exact terminals/new utility; its normal lookup path requires an explicit fixed evaluation binding. Callback overrides are marked as tests. Missing leaves remain unresolved even with an ancestor CP. The native engine retains book re-entry, paired full-key random streams and actual history since the start.
10. **Stronger release checks.** `pilot_acceptance` requires `pilot-acceptance-v2` and content-bound evidence for policy continuity, own calibration, uncertainty accounting, horizon semantics, evaluation binding, native referee, effective objective and input cost, alongside the existing quality/budget/gate checks. An old report containing only true booleans cannot release the matrix.
